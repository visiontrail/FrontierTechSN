# 标题与发布简介的编辑方法

视频制作标题与发布文案标题共用 `backend/prompts/title_strategy.txt`。在 Admin →
Pipeline Prompts → Title editorial strategy 中修改，下一次生成时两条流程都会读取。
最终审核口播是唯一事实依据；来源标题和早期摘要不能替代最终口播。

## Morning Desk 的标题与开头对齐

新研究任务先在已选新闻中确定主新闻：优先取评分最高的新闻报道，保留其余新闻的
相对顺序。`research/dossier.json` 的 `lead_story_id` 锁定主新闻；如果事实审核淘汰
它，则在原位置替换并重新审核。审核按固定段落位置核对来源，不再把错序段落按
关键词重新配对后放行。

主新闻前两句必须说清「谁做了什么」及有证据支持的意义或实际影响，同时保留
归因和限制。写稿预算为最多 34 个英文词或 76 个中文口播单位。独立事实审核会
检查这两句是否覆盖事件和意义；不允许为满足开头要求编造影响。

审核通过后，软件去掉节目问候，把主新闻前两句单独作为视频开头，其余原句接着
播放。保留 `script.reviewed.txt` 和原审核凭证，`rundown.json` 记录最终稿哈希、
新闻编号、顺序及每个口播段落。完成校验会验证最终稿确实只是审核稿的拆分，
不会把改写后的新事实当作已审核内容。

开头从 0 秒进入主新闻口播及对应画面，不插入品牌片头、音乐前奏或开场后的停顿。
这项规则优先于新任务的旧开场与音乐前奏设置，结尾配置仍适用。渲染前按已验证的
TTS 分段或声学对齐检查前两句的实际结束时间；超过 20 秒则阻止渲染，要求缩短、
重新审核及配音，不通过加速音频满足要求。未启用音乐时也执行这一检查。

制作标题只接收主新闻审核口播，不接收其他新闻作为选题；日期后缀由软件按版期
生成。发布文案必须沿用制作标题，各条说明按固定新闻编号输出。自动发布简介
同样按该顺序摘取审核口播。画面和来源网页绑定新闻编号，不能靠相似关键词串到
另一条新闻。

章节从实际配音时间线生成，`chapters.next.json` 只在成片通过最终质量门后转成
`chapters.json`，绑定当前口播、音频和成片版本。没有对应成片时不生成时间戳。
手工编辑口播后，重新生成会按原新闻位置重组审核稿并复审；旧日期、旧章节及旧
审核候选不能覆盖这次编辑。

没有 `lead_story_id` 的历史任务保留原布局，避免升级时改动已有配音及恢复检查点。
新代码需由服务正常重启后加载；修改文件不会自动重启正在生产的任务。

## 编辑顺序

1. 通读成稿，确定观众能从本期获得的主要信息。Morning Desk 使用已经锁定、置于
   最前面的主新闻；其他视频选有实质篇幅的主线，不因知名人物的一笔带过而放大。
2. 判断证据强度：已观察到的结果、当事方说法、计划、局部实验、推测和未解决问题
   要分别表达。可能受数据污染影响的相似回答，不能直接称为独立科学发现。
3. 按内容选择事实句或问题句。已确定的发布用事实句；确实讨论开放问题时才用问句。
   问号不能掩护没有证据的前提，也不强制套用某种句式。
4. 主题和关键变化靠前。英文约 40–65 字符、中文约 10–28 字是编辑目标，
   不是推荐算法阈值。准确性优先，平台硬上限为 100 字符；超长要重写，不能截断。
   每日多新闻简报使用 `主新闻 | Daily Tech Brief · Oct 12` 格式，日期取版期。
5. 模型在内部比较几个候选，按事实忠实、主线代表性、具体程度和可读性挑选一个。
   标题本身不得夸大，再指望简介补救。
6. Show Notes 首 1–2 句承接标题主题和关键限制，再介绍其他新闻与来源。

例如，一项实验仅产生了类似历史科学解释的回答，且成稿承认独立性存疑，
就应围绕“能否重新发现”或“实验显示了什么”措辞；确实已经发布的产品则应
直接写“谁发布了什么”，不生造悬念。所有案例只示范判断方法，不是固定标题。

## 执行与验证边界

两条流程保留各自任务和输出格式，共享编辑策略。新 Morning Desk 的发布文案
复用制作标题；其他视频仍可分别生成标题。
标题及发布文案会记录实际提示词的 SHA-256。程序检查格式和平台限制，最多三次
生成/修正；语义取舍由模型按规则完成，没有用词黑名单冒充事实验证。

发布文案保留原有 Humanizer、X 按语义分段、280 加权字符及来源 URL 校验。
已有视频和已保存文案不会被批量改写；重新生成才使用新的策略。改策略不会
自动上传 YouTube，也不意味着更新后的后端代码已经加载到运行服务。

回归应覆盖：局部实验与重大限制、已确认的新产品、公司尚未兑现的计划、
多故事且开头并非主线、中文内容、超长输出修正和修正失败保留旧产物。
真实模型回放应另行检查标题是否准确、简介是否承接，不能把 mock 测试当成文案质量证明。

参考：YouTube [标题与缩略图建议](https://support.google.com/youtube/answer/12340300?hl=en)
及[展示次数与点击率说明](https://support.google.com/youtube/answer/7628154?hl=en)。
少量展示和作者自己的观看不足以评定标题优劣，也不能据此承诺流量提升。
