# 从单次故障到一类问题的修复

## 修复完成的判据

单条输入不再报错，只证明复现用例被修复。一个完整修复还要明确输入支持范围、归并重复实现、检验不变量和失败路径，并用重启后的原任务验证实际行为。代码提交、服务生效和视频完成分别记录，不能相互替代。

## 排查和实施步骤

1. **保存现场并定位首个错误。** 对齐任务 ID、阶段、完整异常栈、运行版本与输入产物。保留原稿和已完成的音频；提取最小复现，不修改新闻内容来躲过代码错误。
2. **按原因分类。** 确定性的解析/协议错误进入本地预检；网络和服务临时故障才使用有限次数重试；模型输出不合约时依据明确诊断做有界修正；音频、画面、内容和发布检查使用各自的证据。不能把 ASR 拼写差异等同于音频损坏。
3. **检查整条数据路径。** 比较输入、转换、验证、缓存和输出使用的规则。相同概念只保留一份定义；发生不一致时修复契约，避免为新词再添加一条彼此独立的分支。
4. **同时测试等价与非等价输入。** 等价形式必须产生相同结果；数值、单位、精度、顺序、限定词或内容被修改时必须保留差异。除事故用例外，增加边界、组合和固定随机种子的批量检查。
5. **让失败可定位且可恢复。** 错误包含阶段、分段位置、原因及异常类型，日志保留原始异常链。代码错误不反复请求外部服务。缓存仍检查原稿、声音、模型、音频哈希和接受条件；恢复测试验证完整产物被复用。
6. **验证实际运行。** 先测试并提交，再构建/重启；核对 `/api/runtime` 的提交和源码指纹、服务健康、原任务的新日志和前端状态。继续任务后，要实际越过原来的失败点。

## 数字处理的具体契约

`backend/spoken_numbers.py` 共享数字词、倍率、整数拼写和带索引的组合数解析。原稿数字拼写、Pocket TTS 请求准备和 ASR 数字比较使用这份规则。

- 普通非负整数拼写范围为 `0..999,999,999,999`，使用整数运算。组合数按 billion → million → thousand → hundred 的数量级解析，允许标准的 hundred 余数和 `and` 表达。
- 规范的逗号分组在词法比较之前处理；ASR 分成多个词的分组数字保留第一词的时间索引，后续单位和正文索引不变。
- 年份读法、小数、日期、序数、货币和产品标识仍有各自的规则。不能用普通数量规则无条件改写它们。带符号、货币符号、前导零、版本、小数、不规范分组和超出拼写范围的输入不做普通数量拼写改写。
- 未知倍率和未支持形式保留词项，不补零、不猜倍率、不捕获错误后假装成功。重复倍率及额外词项不能被吞掉。整个语音验证器的 ASR 接受策略独立于数字规范化。
- Pocket TTS 在任何远端语音请求之前预检所有分段。预检失败携带段号及异常原因；不会对同一确定性错误反复消耗远端生成。

`backend/tests/test_number_contract.py` 使用所有 `0..999` 系数乘以四个数量级、数量级边界、混合组和固定种子的 1,000 个样本，检查：

1. 整数、逗号数字、口语形式的结果与独立整数值一致。
2. 请求改写保持数值、单位和后续正文。
3. ASR 输出的数字起点、后续单位和正文时间索引正确。
4. 改变数值、替换单位、删掉单位不能得到原结果。
5. 未知倍率、重复词和保护形式的处理有明确边界。

事故回归保留在 `backend/tests/test_tts_number_scales.py`，覆盖报错上下文、整稿预检无远端副作用、成功音频的缓存复用。运行相关检查：

```sh
.venv/bin/python -m pytest backend/tests/test_number_contract.py backend/tests/test_spoken_numbers.py backend/tests/test_tts*.py backend/tests/test_pipeline_parallel.py -q
```

这套方法消除已识别的规则重复和覆盖缺口。新语法、模型行为和外部服务变化仍需要证据与回归测试；每次扩展都应更新契约和测试范围。
